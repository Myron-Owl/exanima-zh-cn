# Steam 小更新自动兼容

此版采用两条加载路径：已核对 EXE 保留完整 SHA256 白名单；未知 EXE 只有通过自动结构检查才启用汉化。不是忽略版本号，也不按“找到第一个相似入口”加载。

## 用户行为

安装一次 `Exanima-zh-CN-0.9.5.2f-Steam.zip` 后，游戏仅移动文字函数、相关数据或原文地址的小更新，可以继续使用现有 DLL、字体和译文。新增或改写的原文未命中词典时显示原文。Steam 若移除了补丁文件，仍需重新覆盖安装。

自动识别不能承诺所有后续版本都兼容。渲染函数内容、字段偏移、调用关系、相关字面量或同名词语语境变化时，会拒绝安装全部文字入口并回退英文，不尝试部分挂钩。9 个带语境限制的词条必须全部定位，不能用第一个同名英文代替。

## 检查内容

- 解析并限制 x64 PE 的文件范围、节范围、异常表及映射大小。
- 核对 11 个文字入口、5 个绘制辅助函数和 6 个直接调用函数的完整规范化 SHA256。
- 只忽略经审核的外部 RIP 地址或外部跳转位移；局部跳转、字段与栈偏移、寄存器选择和其余指令字节全部保留。
- 校验 284 个引用的身份一致性、函数角色、4 个可写引擎字段、节权限及原有渲染字面量。
- 核对 9 个限定词条的完整原文、64 位长度前缀与引用表的类型化语境哈希。同文异义分别匹配；候选不唯一时拒绝。
- 写入入口前，比对已加载进程中的完整函数字节、原文与语境引用位置；任一不一致即停止。

`data/compatibility.json` 是经审核的特征源；`tools/compile_compatibility.py` 生成外部 `ExanimaZh/compatibility.zhc`。配置有格式、范围与 SHA256 完整性检查；DLL 内另固定完整代码/引用特征的摘要与 9 个原文身份，外部配置不能改变这些约束。校验和用于发现损坏，不是数字签名。文件包含哈希、短入口锚点、引用元数据和已公开的词条，不包含完整游戏函数、EXE 或 RPK。

## 本地验证

完整构建自动运行自有 PE 夹具测试，无需原游戏文件：地址整体移动、绘制辅助函数单独移动、同词语境定位、完整词典输出、绘制状态、未来文本英文回退，以及损坏/歧义/结构变化的拒绝检查。初始化测试直接调用生产加载流程，检查通过后才安装全部入口，失败时映射字节不变。

以下命令在完成构建后，只读检测未来 EXE，不执行它，不更改白名单或游戏文件：

```powershell
python -B -X utf8 tools/verify_compatibility.py --detect-exe "<游戏目录>/Exanima.exe"
```

`--game-exe` 用于对已核对版本做回归，另行运行全部词典与模拟绘制检查。检测通过和真实游戏画面验收是不同证据。

日志中 `Verified game profile: steam-...` 表示精确已知版本；`AUTO COMPATIBILITY: ...` 和 `auto-compatible-steam` 表示未知哈希已通过完整结构匹配；`AUTO COMPATIBILITY REFUSED: ...` 会记录回退原因。

## 独立配置的补救范围

若代码与引用身份保持原样，但界面表周围增加了新字段或文本，维护者可在审核新版本配置后，用既有特征源作为 `--baseline-model` 生成新的语境特征，并单独编译配置。无需重新编译 DLL，也无需改变字体或词典。生成工具仍要求实际 EXE 哈希出现在经审核的 `data/versions.json` 中，并拒绝完整函数、调用/数据角色、节权限或渲染字面量变化。

```powershell
python -B -X utf8 tools/generate_compatibility.py --exe "<新 EXE>" --analysis-libs "<本地 pefile/capstone 目录>" --baseline-model data/compatibility.json --output build/reviewed-compatibility.json
python -B -X utf8 tools/compile_compatibility.py --input build/reviewed-compatibility.json --output build/reviewed-compatibility.zhc
```

配置使用已部署模块认识的基线身份，保留原 ABI、函数和引用角色，仅更新已重新核对的词条语境。替换前备份，替换后用同一原生检测器和真实游戏验证。不要把任意新函数哈希或首个原文候选加入配置来放宽检查；真正改变代码或 ABI 时应重新审查运行时并发新模块。

## 当前证据与限制

已用真实 Steam e、f EXE 验证同一份 e 基线配置可以自动推导两版地址，包含 f 版 5 个辅助函数的 `+0x60` 移动。原始游戏文件只在本地作为只读输入，不随源码或补丁分发。f 版已实际启动，日志确认 2,612 条译文与全部 11 个入口成功加载；用户于 2026-10-06 确认设置、操作、异能与羊皮纸显示正常。

2026-10-08 另行核对 Steam 0.9.5.2g build 25803178：未知哈希自动检测通过全部 22 个函数与 9 个限定词条检查，实际启动日志确认自动加载和中文绘制成功。2,612 条译文在 g 版地址布局下完成输出比对与模拟绘制检查；在已提取文本范围内，EXE 相对 f 版只改变版本号，物品、技能、教程、对话和地图书信原文未变，因此无需为该更新重新打包。这是指定 g 构建的核对记录，不保证其他未来版本，也不等于所有游戏画面均已实机验收。

README、署名、制作日期和人工校对 Excel 保持原样。自动兼容机制不会自动翻译新剧情，不改变已人工编辑的译文，也不联网下载配置。
